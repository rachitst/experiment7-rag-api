# Experiment 7 — NestBasket Customer Support RAG API (FastAPI + cloud LLM)

The customer-support RAG assistant from Experiment 6, exposed as a web API with input validation,
controlled error handling, logging and response-time measurement. Answers are generated by a
**cloud-hosted LLM API** (default: Groq, free plan, OpenAI-compatible); retrieval runs locally.

```
experiment7/
├── app.py            # FastAPI app: GET /health, POST /ask, validation, errors, logging, timing
├── support_rag.py    # RAG pipeline (FAQ, chunking, embeddings, FAISS, prompt) + LLM backend
├── support_faq.txt   # knowledge base (fictional NestBasket store FAQ)
├── test_api.py       # endpoint test client (testing checklist)
├── requirements.txt  # Python dependencies
├── .env.example      # configuration template  ->  copy to .env and add your key
└── .gitignore        # keeps .env and logs out of Git
```

## 1. Get a free API key (Groq)

1. Go to https://console.groq.com and sign up (Google, GitHub or e-mail). No credit card is needed for the free plan.
2. Open **API Keys** → **Create API Key**, give it a name (e.g. `exp7`), and copy the key. It is shown only once.
3. Keep the key private: do not paste it into code, screenshots, chats or GitHub.
4. Check **Settings → Limits** in the console for your current free-plan limits.

## 2. Run on your computer (VS Code)

Requires Python 3.10 or newer (https://www.python.org/downloads/ — on Windows tick *"Add python.exe to PATH"*).

Open the `experiment7` folder in VS Code, then **Terminal → New Terminal**:

```bash
# 1. create and activate a virtual environment
python -m venv .venv
.venv\Scripts\activate            # Windows (PowerShell / cmd)
source .venv/bin/activate         # macOS / Linux

# 2. install a CPU-only PyTorch first (much smaller download), then the rest
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt

# 3. configuration: copy the template and paste your key into .env
copy .env.example .env            # Windows
cp .env.example .env              # macOS / Linux
#    then open .env and set  LLM_API_KEY=<your key>

# 4. start the API (the first start downloads the ~90 MB embedding model)
uvicorn app:app --host 127.0.0.1 --port 8000
```

When the terminal shows `rag_ready ...` and `Uvicorn running on http://127.0.0.1:8000`, open
**http://127.0.0.1:8000/docs** → `POST /ask` → **Try it out** → enter a question → **Execute**.

Example body:

```json
{ "question": "How many days do I have to return an unused item?" }
```

## 3. Run the testing checklist

Keep the server running; open a **second** terminal (activate `.venv` again) and run:

```bash
python test_api.py
```

It checks: health endpoint, a supported question, an unsupported question, an empty question,
and a 1,001-character question, and prints client-side and server-side response times.

**Backend-failure test** (no need to edit `.env` — a variable set in the terminal overrides it):

```bash
# Windows PowerShell
$env:LLM_API_KEY="invalid-key-for-testing"; uvicorn app:app --port 8001
# macOS / Linux
LLM_API_KEY=invalid-key-for-testing uvicorn app:app --port 8001
```

Then send a question to `http://127.0.0.1:8001/docs` (or `python test_api.py http://127.0.0.1:8001`).
Expected: **HTTP 503** with `"error": "backend_unavailable"`, no key and no stack trace in the response,
and a log line `ask_failed ... error_kind=authentication_failed upstream_status=401`.
In PowerShell, close that terminal afterwards (or run `Remove-Item Env:LLM_API_KEY`).

## 4. Endpoints and responses

| Request | Result |
|---|---|
| `GET /health` | `200` `{"status": "ok", "index_ready": true, "indexed_chunks": 16, ...}` |
| `POST /ask` with a valid question | `200` with `status` = `answered` or `insufficient_information`, `answer`, `sources`, `latency_ms` |
| Empty / blank / > 1,000 characters / missing / non-text question | `422` `{"error": "invalid_request", "detail": [...]}` |
| LLM provider failure (wrong key, quota, wrong model, network, timeout) | `503` `{"error": "backend_unavailable", ...}` |
| Unexpected server error | `500` `{"error": "internal_error", ...}` (no stack trace) |

Every response carries `X-Request-ID` and `X-Response-Time-ms` headers. Logs are written to the
terminal and to `logs/app.log` (one line per request: request ID, path, status, latency; for `/ask`
also outcome, top section, distance, token counts, retrieval / generation / total time). The question
text and the API key are never logged.

## 5. Configuration (`.env`)

| Variable | Default | Meaning |
|---|---|---|
| `LLM_BASE_URL` | `https://api.groq.com/openai/v1` | OpenAI-compatible endpoint of the provider |
| `LLM_MODEL` | `openai/gpt-oss-20b` | Model identifier at that provider |
| `LLM_API_KEY` | — | Your key (required) |
| `LLM_BACKEND` | `openai_compatible` | `mock` = offline test without a key |
| `LLM_TIMEOUT_SECONDS` | `30` | Maximum wait for the provider |
| `RAG_TOP_K` | `3` | Passages retrieved per question |
| `RAG_MAX_DISTANCE` | `1.5` | If the closest passage is farther than this, answer with the fallback without calling the LLM |

Other OpenAI-compatible providers work by changing `LLM_BASE_URL`, `LLM_MODEL` and `LLM_API_KEY`
(e.g. Hugging Face router `https://router.huggingface.co/v1`, OpenRouter `https://openrouter.ai/api/v1`).

## 6. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `/ask` returns 503, log says `authentication_failed` | Key wrong, revoked, or not loaded — check `.env` (no quotes or spaces around the key) |
| log says `rate_limited_or_quota_exceeded` (429) | Free-plan limit reached — wait a minute / until the daily reset, or use another model |
| log says `model_or_endpoint_not_found` (404) | Model name or base URL wrong / model retired — check the provider's model list |
| log says `network_error` or `timeout` | No internet, firewall/proxy, or provider down |
| log says `configuration_missing_api_key` | `LLM_API_KEY` is empty — create `.env` from `.env.example` |
| `ModuleNotFoundError` | Virtual environment not activated, or `pip install -r requirements.txt` not run |
| Port already in use | Another server is running — stop it (Ctrl+C) or use `--port 8001` |

## Deployment (Experiment 8) — Azure Container Apps

**Application URL:** https://exp7-rag-api.politefield-e1a38991.centralindia.azurecontainerapps.io
(`/health`, `/docs`, `POST /ask`)

| | |
|---|---|
| Platform | Azure Container Apps, environment `cae-exp7-rag-api` (WorkloadProfiles mode, Consumption profile) |
| Region | Central India (`centralindia`) |
| Resource group | `rg-exp7-rag-api` (registry, environment, app, one Log Analytics workspace) |
| CPU / memory | 1.0 vCPU / 2 GiB per replica |
| Scaling | 0 – 2 replicas (scales to zero after 300 s without traffic) |
| Image | `acrexp7rag5973.azurecr.io/exp7-rag-api:v1`, 584.5 MB compressed, Basic-tier ACR |
| Registry auth | system-assigned managed identity with `AcrPull` — the registry admin user is disabled, no password anywhere |
| API key | stored only as the Container Apps secret `llm-api-key`; the container gets it as `LLM_API_KEY=secretref:llm-api-key` |

### How the image is built

The `Dockerfile` installs CPU-only PyTorch and `requirements.txt` on `python:3.11-slim`, and bakes the
`all-MiniLM-L6-v2` embedding model into the image so a new replica does not download it at start-up.
The plan was to build in the cloud with `az acr build`, but ACR Tasks are not permitted on
**Azure for Students** subscriptions (`TasksOperationsNotAllowed`). The image is therefore built with local
Docker and pushed with an Entra ID login (`az acr login`, no admin credentials).

### Commands (key masked)

```bash
LOCATION=centralindia; RG=rg-exp7-rag-api; ACR=acrexp7rag5973; ENV_NAME=cae-exp7-rag-api; APP=exp7-rag-api

az group create -n $RG -l $LOCATION
az acr create -n $ACR -g $RG --sku Basic --admin-enabled false

# image (az acr build is blocked on Azure for Students -> local build + push)
docker build -t exp7-rag-api .
az acr login -n $ACR
docker tag exp7-rag-api $ACR.azurecr.io/exp7-rag-api:v1
docker push $ACR.azurecr.io/exp7-rag-api:v1
az acr repository show-tags -n $ACR --repository exp7-rag-api

# environment: WorkloadProfiles mode (the default "Express" mode rejects managed-identity registry pull)
az containerapp env create -n $ENV_NAME -g $RG -l $LOCATION --environment-mode WorkloadProfiles \
  --logs-workspace-id <workspace customerId> --logs-workspace-key <workspace key>

az containerapp create -n $APP -g $RG --environment $ENV_NAME \
  --image $ACR.azurecr.io/exp7-rag-api:v1 \
  --registry-server $ACR.azurecr.io --registry-identity system \
  --target-port 8000 --ingress external \
  --cpu 1.0 --memory 2.0Gi --min-replicas 0 --max-replicas 2 \
  --env-vars LLM_BACKEND=openai_compatible LLM_BASE_URL=https://api.groq.com/openai/v1 LLM_MODEL=openai/gpt-oss-20b \
             LLM_TIMEOUT_SECONDS=30 LLM_MAX_TOKENS=300 RAG_TOP_K=3 RAG_MAX_DISTANCE=1.5

az containerapp secret set -n $APP -g $RG --secrets llm-api-key=gsk_****
az containerapp update -n $APP -g $RG --set-env-vars LLM_API_KEY=secretref:llm-api-key
URL=https://$(az containerapp show -n $APP -g $RG --query properties.configuration.ingress.fqdn -o tsv)

# verification
python test_api.py $URL
az containerapp logs show -n $APP -g $RG --type console --tail 100
```
